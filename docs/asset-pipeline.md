# 3D asset pipeline — Blender (bpy) → GLB → React Three Fiber

Hard-surface assets for THE ORBIT are generated by script, not modelled by hand, so
every object is reproducible and reviewable as a diff.

## Why headless bpy rather than the Blender application

Blender is not installed on this machine and is not required. `bpy` publishes a
`cp313` wheel matching the project's Python 3.13, which is the **complete Blender
Python API running headless** — bevel modifiers, weighted normals, booleans,
smooth-by-angle and the official glTF exporter, all without a GUI.

This is Option B from the asset brief: *Blender Python scripts generating the
hard-surface objects, exported as GLB.*

## Environment

Isolated in a project virtual environment. **The global Python environment is
deliberately untouched** — verify with `python -m pip show bpy`, which should
report the package as not found.

```bash
# One-time setup, from the project root
python -m venv .venv-blender
.venv-blender/Scripts/python.exe -m pip install "bpy==5.2.0"
```

Version is pinned. `bpy` bundles the entire Blender runtime, so a minor version
bump can silently change modifier or exporter behaviour; upgrades must be
deliberate and re-verified against the pipeline test below.

| | |
| --- | --- |
| Python | 3.13.14 |
| bpy | 5.2.0 (pinned) |
| venv | `.venv-blender/` — git-ignored, ~1 GB |

## Commands

```bash
# 1. Verify the pipeline end to end (run this before any modelling work)
.venv-blender/Scripts/python.exe tools/blender/verify_pipeline.py

# 2. Generate the Brand World
.venv-blender/Scripts/python.exe tools/blender/brand_world.py

# 3. Generate the Maps Lead Scraper satellite
.venv-blender/Scripts/python.exe tools/blender/maps_scraper.py
```

All scripts write to `public/models/` and print a `PIPELINE_REPORT {…}` line
carrying triangle count, byte size and material list, so every export is measured
rather than estimated.

## What the verification script proves

`tools/blender/verify_pipeline.py` builds one minimal object that exercises every
feature the real assets depend on. If any of these fail to survive export, the
approach is wrong and we find out in seconds instead of after hours of modelling:

| Feature | Why it matters |
| --- | --- |
| Bevel modifier, 3 segments, harden normals | Bevels catching light are the single biggest difference between a hard-surface asset and a primitive |
| Weighted normals | Keeps large flat panels reading flat next to bevelled edges |
| Smooth-by-angle | Clean curvature without faceting |
| Boolean difference | Recessed seams and panel channels |
| Two PBR materials on one mesh | Material separation must survive as separate glTF primitives |
| Applied non-uniform scale | Confirms the asset arrives 1:1 in Three.js |
| `export_yup=True` | Blender is Z-up, Three.js is Y-up |

## Known Blender → glTF material limitations

Recorded before modelling, because the material direction has to be authored
around them:

- **Only the Principled BSDF exports.** Arbitrary node graphs are lost. All
  materials in these scripts use Principled and nothing else.
- **Transmission (smoked glass) exports via `KHR_materials_transmission`**, which
  Three.js reads into `MeshPhysicalMaterial.transmission`. Thickness needs
  `KHR_materials_volume`; without it glass renders flat rather than solid.
- **Clearcoat** maps through `KHR_materials_clearcoat` — supported, but adds a
  render cost worth spending only on the ceramic panels.
- **Emission strength above 1.0** requires `KHR_materials_emissive_strength`.
  Since the brief caps emissive at roughly 5% of visible surface, internal lights
  are driven in Three.js rather than baked, keeping the object convincing with
  emission switched off.
- **Blender's Cycles preview will not match the browser.** The browser uses
  Three.js's PBR approximation with an environment map, ACES tone mapping and
  sRGB output. The browser is the source of truth for review — Blender viewport
  differences are expected and are documented per asset.

## LOD strategy

Visual quality first. Only once the high-quality asset passes review are
`-balanced` and `-mobile` variants generated by reducing bevel segments and
booleaned detail — never by decimating, which destroys silhouette and bevels.
